BloodKnight.leads — учёт заявок из веб-форм

Установка на демо-сайт 1С-Битрикс «Управление сайтом», Стандарт
1. Распакуйте архив в корень сайта. Файл install/index.php должен оказаться внутри /local/modules/bloodknight.leads/. Требуются MySQL/MariaDB, модуль form и штатная обработка ЧПУ.
2. В настройках сайта укажите доменное имя без схемы. При пустом поле модуль использует основную настройку server_name. Домен должен обслуживаться по HTTPS.
3. Предоставьте PHP права записи в /bitrix/admin/, правила urlrewrite.php сайта и файл /local/modules/bloodknight.leads/logs/overdue.php.
4. Откройте «Marketplace → Установленные решения» и установите BloodKnight.leads. Путь /lead/ зарезервирован для подтверждений.
5. В почтовый шаблон менеджера события FORM_FILLING_<SID> добавьте #STATUS_LINK#. Для HTML-письма используйте <a href="#STATUS_LINK#">Подтвердить обработку</a>. Оставьте ссылку только в шаблоне менеджера. Переход по ссылке меняет статус без авторизации. Автоматический просмотр ссылок почтовым сервисом также может подтвердить заявку.

Проверка после установки
Отправьте веб-форму дважды. В разделе «Сервисы → Заявки веб-форм» должны появиться две строки со статусом «Не обработана». Проверьте сортировку по дате и фильтр по статусу. При наличии более 20 строк доступна следующая страница.
Откройте ссылку из первого письма. Должно появиться сообщение «Заявка обработана.», при повторном переходе — «Заявка уже обработана.». Проверьте, что вторая заявка осталась необработанной. Подмена кода на неизвестный должна вернуть HTTP 404.
Агент выполняется раз в час штатным планировщиком Битрикс. Каждый запуск добавляет в logs/overdue.php текстовую строку для каждой всё ещё не обработанной заявки возрастом от восьми часов. Журнал читается с файловой системы. На демосайте с агентами на хитах для запуска нужен трафик.
Учет начинается с установки. IP берётся из REMOTE_ADDR. За обратным прокси настройте передачу реального IP на уровне веб-сервера.

Удаление
Штатное удаление модуля удаляет таблицу со всеми заявками, агент, подписки на события, правило ЧПУ и административную страницу. Журнал остаётся в каталоге модуля. Если он нужен, скопируйте его перед удалением каталога.

Маршрут подтверждения
Установщик создаёт /lead/index.php и добавляет правило /lead/[CODE] в urlrewrite.php.
Для установки PHP должен иметь право создать каталог lead в корне сайта.
Если модуль уже установлен и в таблице есть заявки, сохраните данные перед удалением модуля.
Для обновления одного маршрута на установленном модуле скопируйте install/lead.php в /lead/index.php. Если прежнее правило /lead/ уже работает, оно по-прежнему направляет запросы в public/status.php.
